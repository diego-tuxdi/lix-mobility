# 07-restrictions.md

# Restricciones del Proyecto

Este documento define las reglas que deben respetarse durante todo el desarrollo.

Si existe una contradicción entre una decisión automática de la IA y este documento, siempre prevalece este documento.

---

# Producto

No modificar la propuesta de valor.

Lix vende movilidad.

No vende turismo.

No vende embarcaciones.

No vende experiencias recreativas.

Toda decisión debe reforzar la idea de:

"La nueva forma de moverte por el agua."

---

# Alcance

El proyecto es un MVP.

No agregar funcionalidades fuera del SOW.

No agregar nuevas páginas.

No crear secciones adicionales.

No agregar:

- Blog
- Noticias
- Casos de éxito
- Clientes
- Prensa
- Carreras
- Marketplace
- Dashboard
- Login
- Registro

La web únicamente presenta el producto.

---

# Contenido

No inventar contenido.

No inventar beneficios.

No inventar funcionalidades.

No inventar estadísticas.

No inventar usuarios.

No inventar testimonios.

No inventar empresas que utilicen Lix.

No inventar premios.

No inventar certificaciones.

---

# Copy

Utilizar únicamente el contenido definido en:

05-copy.md

Si falta contenido deberá dejarse indicado.

Nunca completarlo automáticamente.

---

# Assets

Utilizar únicamente assets oficiales.

No reemplazar:

mockups

pantallas

ilustraciones

logos

fotografías

por alternativas generadas automáticamente.

Si un asset falta deberá dejarse un placeholder claramente identificado.

Nunca buscar imágenes de stock automáticamente.

---

# Aplicación

Nunca rediseñar la aplicación.

Nunca modificar:

pantallas

componentes

tipografía

colores

iconografía

Los mockups deben mostrar exactamente la aplicación existente.

---

# Diseño

No copiar Uber.

No copiar Cabify.

Utilizarlos únicamente como referencia de calidad.

La identidad visual debe sentirse propia.

---

# Estética

Evitar:

gradientes exagerados

fondos recargados

efectos glass pesados

neumorphism

3D

texturas

ruido

patrones invasivos

animaciones excesivas

---

# Fotografías

No utilizar imágenes de:

playas

vacaciones

turismo

cruceros

pesca

deportes acuáticos

barcos antiguos

marinas deportivas

atardeceres dramáticos

La fotografía debe transmitir movilidad urbana.

---

# Ilustraciones

No generar nuevas ilustraciones.

Utilizar únicamente las oficiales.

Las ilustraciones son un recurso secundario.

Nunca reemplazan fotografías.

Nunca reemplazan mockups.

---

# Mockups

No generar interfaces.

No recrear pantallas.

No modificar componentes.

No mezclar pantallas inexistentes.

Utilizar únicamente capturas reales.

---

# Animaciones

No utilizar:

scroll hijacking

parallax complejo

rotaciones

zoom infinito

efectos de partículas

cursores personalizados

animaciones continuas innecesarias

Las animaciones deben ser discretas.

---

# Navegación

No utilizar:

sliders

carouseles

tabs complejos

mega menus

scroll horizontal

La navegación debe ser simple.

---

# Componentes

No crear múltiples variantes innecesarias.

Priorizar reutilización.

Cada componente debe tener una única responsabilidad.

---

# Responsive

Nunca ocultar contenido importante en mobile.

No crear experiencias distintas.

La información debe mantenerse consistente.

---

# Código

No dejar código muerto.

No comentar bloques innecesarios.

No duplicar lógica.

No hardcodear valores.

No utilizar librerías innecesarias.

---

# Dependencias

Antes de agregar una dependencia responder:

¿Resuelve un problema real?

Si la respuesta es no,

no instalarla.

---

# Performance

No sacrificar performance por efectos visuales.

La carga debe sentirse inmediata.

---

# SEO

No utilizar textos ocultos.

No duplicar títulos.

No repetir keywords artificialmente.

---

# Accesibilidad

Nunca depender únicamente del color.

Todos los elementos interactivos deben ser accesibles mediante teclado.

---

# IA

Si una decisión no está documentada:

NO asumir.

Consultar.

---

# Prioridades

Siempre priorizar en este orden.

1.

Claridad.

2.

Producto.

3.

Experiencia.

4.

Estética.

5.

Animaciones.

Nunca invertir ese orden.

---

# Filosofía

Si una decisión hace la landing más llamativa pero menos clara,

es la decisión incorrecta.

La claridad siempre gana.

---

# Definición de éxito

Una persona que nunca escuchó hablar de Lix debe poder responder, después de menos de dos minutos:

✓ Qué es.

✓ Cómo funciona.

✓ Por qué usarla.

✓ Cómo descargarla.

✓ Cómo convertirse en Capitán.

Si alguna de esas respuestas no está clara,

la implementación no cumple con la especificación.
